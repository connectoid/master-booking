# master-booking — онлайн-запись для частных мастеров

Простая и дешёвая онлайн-запись для мастеров-одиночек и маленьких салонов (1–3 кресла)
с напоминаниями клиентам в мессенджере. Первая ниша — бьюти (парикмахеры, маникюр),
но ядро универсальное: «услуга — длительность — слот».

## Порядок платформ
1. **MAX** (бот + Mini App) — первым. Бот создаётся на платформе для партнёров MAX
   (нужна верификация ИП, резидент РФ).
2. **Telegram** (бот + Mini App).
3. **Браузер** — та же Mini App по обычной ссылке.

## Ключевые архитектурные решения
- **Мультиарендность с первого дня**: один бот и одна БД на всех мастеров.
  Мастер идентифицируется по `masters.slug`; ссылка клиента несёт slug в start-параметре.
- **Ядро не знает про мессенджеры.** Всё, что зависит от платформы, живёт в
  `backend/app/channels/<channel>/`. Ядро оперирует `Channel` (`max | telegram | web`)
  и парой `(channel, external_user_id, chat_id)`.
- **Один фронтенд** (`webapp/`) для MAX, Telegram и браузера; платформа определяется
  при запуске (MAX Bridge / Telegram WebApp / обычная страница).
- **Время**: в БД только `timestamptz` (UTC). Часовой пояс — у мастера (`masters.timezone`,
  IANA). График работы хранится в локальном времени мастера.
- **Двойная запись невозможна на уровне БД**: EXCLUDE-ограничение по
  `(master_id, tstzrange(starts_at, ends_at))` для активных записей (`pending`, `confirmed`).
- **Напоминания** — таблица `reminders` + планировщик внутри бэкенда
  (выборка `FOR UPDATE SKIP LOCKED`), не n8n и не cron.
- **Проверка входа в Mini App**: HMAC-SHA256 initData; ключ = HMAC("WebAppData", BOT_TOKEN).
  Алгоритм одинаков для MAX и Telegram — `app/channels/webapp_auth.py`.
- **Персональные данные клиентов (152-ФЗ)** — БД только на сервере в РФ.

## Стек
- Python 3.12, FastAPI, SQLAlchemy 2.0 (async, asyncpg), Alembic, PostgreSQL 16.
- MAX: неофициальная `maxapi` или прямые HTTP-вызовы — держать адаптер тонким.
- Telegram: aiogram 3.
- Фронтенд: React + MAX UI (решим на этапе Mini App).

## Чего НЕ делаем в MVP
Онлайн-оплата клиентами, склад, зарплаты, аналитика, нативные приложения.

## Структура
```
backend/
  app/
    config.py              настройки (env)
    db.py                  движок/сессии
    models.py              ORM-модели
    domain/slots.py        расчёт свободных слотов (чистая функция, без БД)
    channels/webapp_auth.py проверка initData Mini App (MAX/Telegram)
    channels/max/          адаптер MAX (todo)
    channels/telegram/     адаптер Telegram (todo)
    main.py                FastAPI
  migrations/              Alembic
  tests/
webapp/                    Mini App (todo)
```

## Окружение
- Разработка и запуск — на VPS (Ubuntu 24.04). На Mac только код:
  интернет спутниковый (~4 Мбит/с, пинг ~800 мс), тяжёлые загрузки на Mac избегать.
- Тесты: `cd backend && pytest`. Интеграционные тесты БД требуют
  `TEST_DATABASE_URL` (пропускаются без него).

## Соглашения
- Код и идентификаторы — на английском, тексты для пользователей и комментарии — на русском.
- Чистая доменная логика (слоты, правила) — без зависимостей от БД и фреймворков, с тестами.
- Деньги — целые рубли (`int`), в MVP без копеек.
